## Overview

The Scout agent performs fast codebase reconnaissance and returns compressed, structured findings that other agents can use without re-reading files.

Scout operates in an isolated context window to keep the main conversation clean. The agent explores the codebase and returns a report, not the raw files.

## When to Use Scout

Use Scout when you need to:
- Locate implementation of a feature across multiple files
- Understand how a system component works
- Find dependencies between modules
- Gather context before starting a task

**Don't use Scout for:**
- Reading a single known file (use Read tool directly)
- Simple grep searches (use Grep tool directly)
- Modifying code (use Worker agent)

## Thoroughness Levels

Scout adjusts exploration depth based on task requirements:

<ResponseField name="Quick" type="level">
  Targeted lookups, key files only. Use for simple questions or well-scoped tasks.
</ResponseField>

<ResponseField name="Medium" type="level" default>
  Follow imports, read critical sections. Default level for most tasks.
</ResponseField>

<ResponseField name="Thorough" type="level">
  Trace all dependencies, check tests and types. Use for complex refactoring or architecture questions.
</ResponseField>

## Strategy

Scout follows a systematic approach:

<Steps>
  <Step title="Locate relevant code">
    Use grep/find to identify files containing relevant keywords, functions, or patterns
  </Step>
  <Step title="Read key sections">
    Read specific sections of files (not entire files) to understand structure
  </Step>
  <Step title="Identify types and interfaces">
    Extract type definitions, interfaces, and function signatures
  </Step>
  <Step title="Note dependencies">
    Track imports, exports, and relationships between files
  </Step>
</Steps>

export async function createCheckoutSession(
  userId: string,
  planId: string
): Promise<Stripe.Checkout.Session> {
  const session = await stripe.checkout.sessions.create({
    customer: userId,
    line_items: [{ price: planId, quantity: 1 }],
    mode: 'subscription',
    success_url: `${process.env.BASE_URL}/checkout/success?session_id={CHECKOUT_SESSION_ID}`,

## Architecture

Three-layer architecture:

1. **Route handler** (`checkout.ts`) - HTTP layer, auth, validation
2. **Service layer** (`stripe.ts`) - Stripe API integration
3. **Database layer** (`subscription.ts`) - Persistence

Flow: Client → POST /checkout → createCheckoutSession() → Stripe API → DB → Response

Session IDs stored locally for webhook correlation (see S03 plan).

## Best Practices

<Tip>
  Always include exact line ranges. "See `file.ts`" is not helpful — "See `file.ts:45-67`" is.
</Tip>

### Do

- **Specify line ranges** for all file references
- **Extract key code** rather than describing it
- **Explain relationships** between components
- **Recommend starting points** with rationale
- **Be concise** — other agents will read this report

### Don't

- **Include entire files** — extract relevant sections only
- **Describe code** when you can show it
- **List every file** — focus on key files
- **Use vague references** — be specific with line numbers
