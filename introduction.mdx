# Introduction to GSD 2

**GSD 2** is a standalone coding agent that builds software autonomously. It's the evolution of [Get Shit Done v1](https://github.com/gsd-build/get-shit-done), which went viral as a prompt framework for Claude Code.

<Note>
  The original GSD showed what was possible. GSD 2 delivers it.
</Note>

## What Makes GSD 2 Different

The first version of GSD was a collection of markdown prompts installed into `~/.claude/commands/`. It relied entirely on the LLM reading those prompts and doing the right thing. That worked surprisingly well — but it had hard limits.

GSD 2 is not a prompt framework. It's a **TypeScript application built on the [Pi SDK](https://github.com/badlogic/pi-mono)** that gives you direct programmatic control over the agent harness itself.

### What This Means For You

One command. Walk away. Come back to a built project with clean git history.

```bash
npm install -g gsd-pi
```

## The Core Concept

GSD structures work into a hierarchy:

```
Milestone  →  a shippable version (4-10 slices)
  Slice    →  one demoable vertical capability (1-7 tasks)
    Task   →  one context-window-sized unit of work
```

<Info>
  **The iron rule:** A task must fit in one context window. If it can't, it's two tasks.
</Info>

Each slice flows through phases automatically:

<Steps>
  <Step title="Research">
    Scout the codebase and relevant docs. Understand what exists and what's needed.
  </Step>
  <Step title="Plan">
    Decompose the slice into tasks with must-haves (mechanically verifiable outcomes).
  </Step>
  <Step title="Execute">
    Run each task in a fresh context window with only the relevant files pre-loaded.
  </Step>
  <Step title="Complete">
    Write the summary, UAT script, mark the roadmap, and commit.
  </Step>
  <Step title="Reassess">
    Check if the roadmap still makes sense given what was learned.
  </Step>
</Steps>

## v1 vs v2: What Changed

| Feature | v1 (Prompt Framework) | v2 (Agent Application) |
|---------|----------------------|-----------------------|
| **Runtime** | Claude Code slash commands | Standalone CLI via Pi SDK |
| **Context management** | Hope the LLM doesn't fill up | Fresh session per task, programmatic |
| **Auto mode** | LLM self-loop | State machine reading `.gsd/` files |
| **Crash recovery** | None | Lock files + session forensics |
| **Git strategy** | LLM writes git commands | Programmatic branch-per-slice, squash merge |
| **Cost tracking** | None | Per-unit token/cost ledger with dashboard |
| **Stuck detection** | None | Retry once, then stop with diagnostics |
| **Timeout supervision** | None | Soft/idle/hard timeouts with recovery steering |
| **Context injection** | "Read this file" | Pre-inlined into dispatch prompt |
| **Skill discovery** | None | Auto-detect and install relevant skills during research |

## Two Modes of Operation

### Step Mode — Stay in the Loop

Type `/gsd` and GSD executes one unit of work at a time, pausing between each with a wizard showing what completed and what's next.

```bash
gsd
/gsd
```

Same state machine as auto mode, but you stay in control. No project yet? It starts the discussion flow. Roadmap exists? It plans or executes the next step.

### Auto Mode — Walk Away

Type `/gsd auto` and let it run. GSD researches, plans, executes, verifies, commits, and advances through every slice until the milestone is complete.

```bash
gsd
/gsd auto
```

<Warning>
  Auto mode is a state machine driven by files on disk. It creates fresh agent sessions, injects focused prompts with all relevant context pre-inlined, and dispatches work units until the milestone completes.
</Warning>

**What happens under the hood:**

- **Fresh session per unit** — Every task, research phase, and planning step gets a clean context window
- **Context pre-loading** — The dispatch prompt includes inlined task plans, slice plans, prior summaries, dependency info, roadmap excerpts, and decisions
- **Git branch-per-slice** — Each slice gets its own branch (`gsd/M001/S01`). Tasks commit atomically. When the slice completes, it's squash-merged to main as one clean commit
- **Crash recovery** — A lock file tracks the current unit. If the session dies, the next run reads the surviving session file and resumes with full context
- **Stuck detection** — If the same unit dispatches twice (the LLM didn't produce the expected artifact), it retries once with diagnostics. If it fails again, auto mode stops
- **Timeout supervision** — Soft timeout warns the LLM to wrap up. Idle watchdog detects stalls. Hard timeout pauses auto mode
- **Cost tracking** — Every unit's token usage and cost is captured, broken down by phase, slice, and model
- **Adaptive replanning** — After each slice completes, the roadmap is reassessed

## The Real Workflow

Run auto mode in one terminal, steer from another.

<CodeGroup>

```bash Terminal 1 — Let it build
gsd
/gsd auto
```

```bash Terminal 2 — Steer while it works
gsd
/gsd discuss    # talk through architecture decisions
/gsd status     # check progress
/gsd queue      # queue the next milestone
```

</CodeGroup>

Both terminals read and write the same `.gsd/` files on disk. Your decisions in terminal 2 are picked up automatically at the next phase boundary — no need to stop auto mode.

## Use Any Model

GSD isn't locked to one provider. It runs on the [Pi SDK](https://github.com/badlogic/pi-mono), which supports **20+ model providers** out of the box:

- Anthropic (Claude)
- OpenAI (GPT)
- Google (Gemini)
- OpenRouter (hundreds of models)
- GitHub Copilot
- Amazon Bedrock
- Azure OpenAI
- Groq, Cerebras, Mistral, xAI, and more

<Tip>
  Use different models for different phases — Opus for planning, Sonnet for execution, a fast model for research. GSD tracks cost per-model so you can see exactly where your budget goes.
</Tip>

If you have a **Claude Max**, **Codex**, or **GitHub Copilot** subscription, you can use those directly via OAuth — no API key needed.
