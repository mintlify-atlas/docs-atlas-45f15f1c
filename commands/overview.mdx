## Command Structure

Most GSD commands follow a consistent pattern:

```bash
/gsd <subcommand> [options] [scope]
```

### Scope Patterns

Many commands accept scope arguments to target specific work units:

- `M001` - Target a specific milestone
- `M001/S02` - Target a specific slice
- `M001/S02/T003` - Target a specific task

### Common Options

- `--verbose` - Enable detailed output (auto mode)
- Global options are configured via `/gsd prefs`

## Quick Reference

| Command | Purpose | Example |
|---------|---------|--------|
| `/gsd` | Start step mode | `/gsd` |
| `/gsd auto` | Start autonomous mode | `/gsd auto` |
| `/gsd stop` | Stop auto/step mode | `/gsd stop` |
| `/gsd status` | View dashboard | `/gsd status` |
| `/gsd queue` | Manage milestones | `/gsd queue` |
| `/gsd discuss` | Plan interactively | `/gsd discuss` |
| `/gsd prefs` | Edit preferences | `/gsd prefs global` |
| `/gsd doctor` | Audit state | `/gsd doctor audit M001` |
| `/gsd migrate` | Migrate from v1 | `/gsd migrate ~/project/.planning` |
| `/worktree` | Create worktree | `/worktree feature` |
| `/voice` | Toggle voice input | `/voice` |

## State Files

GSD commands read and write structured files in `.gsd/`:

- **PROJECT.md** - Project overview and goals
- **REQUIREMENTS.md** - User requirements registry
- **DECISIONS.md** - Architectural decisions
- **STATE.md** - Current execution state (auto-generated)
- **milestones/M###/** - Milestone artifacts
- **milestones/M###/S##/** - Slice artifacts
- **milestones/M###/S##/tasks/** - Task artifacts

See [Architecture](/advanced/state-management) for details on the state machine and file structure.
