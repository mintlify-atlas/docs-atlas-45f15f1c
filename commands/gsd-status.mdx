The `/gsd status` command opens a full-screen dashboard showing milestone progress, slice completion, and recent activity.

## Syntax

```bash
/gsd status
```

## Dashboard Layout

The status dashboard shows:

1. **Active milestone** - Current M### with title and progress
2. **Active slice** - Current S## with title and task completion
3. **Phase indicator** - Current execution phase (planning, executing, etc.)
4. **Milestone registry** - All milestones with status icons
5. **Requirements summary** - Active, validated, deferred, out-of-scope counts
6. **Recent decisions** - Latest architectural decisions
7. **Blockers** - Active issues preventing progress
8. **Next action** - What will happen next in auto/step mode

## State Derivation

The dashboard reads `.gsd/STATE.md` (auto-generated):

```markdown
# GSD State

**Active Milestone:** M001 — Build authentication system
**Active Slice:** S03 — Add session management
**Phase:** executing
```

## Implementation

The status command is implemented in `commands.ts:178`:

```typescript
async function handleStatus(ctx: ExtensionCommandContext): Promise<void> {
  const basePath = process.cwd();
  const state = await deriveState(basePath);

  if (state.registry.length === 0) {
    ctx.ui.notify("No GSD milestones found. Run /gsd to start.", "info");
    return;
  }

  await ctx.ui.custom<void>(
    (tui, theme, _kb, done) => {
      return new GSDDashboardOverlay(tui, theme, () => done());
    },
    {
      overlay: true,
      overlayOptions: {
        width: "70%",
        minWidth: 60,
        maxHeight: "90%",
        anchor: "center",
      },
    },
  );
}
```

## Dashboard Overlay

The `GSDDashboardOverlay` class in `dashboard-overlay.ts` handles rendering:

```typescript
export class GSDDashboardOverlay {
  constructor(
    private tui: TUI,
    private theme: Theme,
    private onClose: () => void,
  ) {}

  render(width: number, height: number): string[] {
    const state = deriveStateSync(process.cwd());
    const lines: string[] = [];

    // Title bar
    lines.push(this.renderTitleBar(width));
    lines.push("");

    // Active milestone
    if (state.activeMilestone) {
      lines.push(...this.renderMilestone(state.activeMilestone, width));
      lines.push("");
    }

    // Active slice
    if (state.activeSlice) {
      lines.push(...this.renderSlice(state.activeSlice, width));
      lines.push("");
    }

    // Phase and next action
    lines.push(this.renderPhase(state, width));
    lines.push("");

    // Separator
    lines.push(this.theme.fg("dim", "─".repeat(width - 4)));
    lines.push("");

    // Milestone registry
    lines.push(...this.renderRegistry(state.registry, width));
    lines.push("");

    // Requirements summary
    if (state.requirements) {
      lines.push(this.renderRequirements(state.requirements, width));
      lines.push("");
    }

    // Recent decisions
    if (state.recentDecisions.length > 0) {
      lines.push(...this.renderDecisions(state.recentDecisions, width));
      lines.push("");
    }

    // Blockers
    lines.push(this.renderBlockers(state.blockers, width));
    lines.push("");

    // Footer
    lines.push(this.theme.fg("dim", "─".repeat(width - 4)));
    lines.push("");
    lines.push(this.renderFooter(width));

    return lines;
  }

  handleInput(data: string): void {
    if (isKeyRelease(data)) return;
    if (matchesKey(data, Key.escape) || matchesKey(data, Key.enter)) {
      this.onClose();
    }
  }
}
```

## State File Updates

The dashboard always shows live state. `STATE.md` is automatically regenerated:

1. **After each unit** - Auto mode rebuilds STATE.md
2. **After doctor fixes** - Doctor writes updated STATE.md
3. **On manual edits** - Run `/gsd doctor fix` to rebuild

```typescript
export async function rebuildState(basePath: string): Promise<void> {
  const state = await deriveState(basePath);
  const path = resolveGsdRootFile(basePath, "STATE");
  await saveFile(path, buildStateMarkdown(state));
}
```

## Requirements Summary

Parsed from `REQUIREMENTS.md`:

```typescript
export interface RequirementsSummary {
  active: number;       // Status: Active
  validated: number;    // Status: Validated
  deferred: number;     // Status: Deferred
  outOfScope: number;   // Status: Out of scope
}

function parseRequirementsSummary(content: string): RequirementsSummary {
  const blocks = content.split(/^###\s+/m).slice(1);
  const summary = { active: 0, validated: 0, deferred: 0, outOfScope: 0 };
  
  for (const block of blocks) {
    const status = block.match(/^-\s+Status:\s+(.+)$/m)?.[1]?.trim().toLowerCase();
    if (status === "active") summary.active++;
    else if (status === "validated") summary.validated++;
    else if (status === "deferred") summary.deferred++;
    else if (status === "out of scope") summary.outOfScope++;
  }
  
  return summary;
}
```

<Tip>
**Use Ctrl+Alt+G during auto mode.** You can open the dashboard without stopping auto-mode to check progress.
</Tip>

<Info>
**Check blockers regularly.** If auto mode stops unexpectedly, `/gsd status` shows why (usually a blocker was discovered).
</Info>

## Troubleshooting

### Dashboard shows outdated info

**Symptom:** Status doesn't reflect recent changes

**Solution:**
```bash
# Rebuild STATE.md
/gsd doctor fix

# Check again
/gsd status
```

### No milestones shown

**Symptom:** "No GSD milestones found"

**Solution:**
```bash
# Start a new project
/gsd discuss

# Or check if you're in the right directory
pwd
ls .gsd/
```
