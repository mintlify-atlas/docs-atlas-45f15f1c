The `/gsd discuss` command opens an interactive planning interface for refining requirements, milestones, and the project queue.

## Syntax

```bash
/gsd discuss
```

## Purpose

Use `/gsd discuss` to:

- Add new milestones to the queue
- Refine existing milestone goals
- Reorder milestones by priority
- Discuss requirements and constraints
- Update project context before planning

## Workflow

The discuss command guides you through an interactive conversation to gather project context and define work scope.

### Initial Project Setup

When starting a new project (no `.gsd/` directory exists):

1. **Discusses project goals** - What are you building?
2. **Gathers requirements** - User needs, constraints, technical requirements
3. **Defines first milestone** - Breaking the project into deliverable chunks
4. **Writes planning artifacts** - PROJECT.md, REQUIREMENTS.md, QUEUE.md

### Adding Milestones

When the project already has active work:

1. **Reviews current state** - Shows active milestone, completed work
2. **Discusses new scope** - What additional functionality is needed?
3. **Creates milestone stub** - Writes CONTEXT.md for later planning
4. **Updates queue** - Adds to QUEUE.md with priority

## State Files Written

### First Invocation

Creates initial project structure:

```
.gsd/
  PROJECT.md           # Project overview and goals
  REQUIREMENTS.md      # User requirements registry
  DECISIONS.md         # Architectural decisions
  QUEUE.md            # Milestone queue
  milestones/
    M001/
      M001-CONTEXT.md  # First milestone context
```

### Adding Milestones

Appends to existing structure:

```
.gsd/
  QUEUE.md            # Updated with new milestone
  milestones/
    M002/
      M002-CONTEXT.md  # New milestone context
```

## Smart Entry Flow

The `showSmartEntry` function in `guided-flow.ts:246` orchestrates the discussion:

```typescript
export async function showSmartEntry(
  ctx: ExtensionCommandContext,
  pi: ExtensionAPI,
  base: string,
  options?: { step?: boolean },
): Promise<void> {
  const state = await deriveState(base);
  
  if (state.registry.length === 0) {
    // New project - full discuss flow
    return showDiscuss(ctx, pi, base);
  }
  
  if (state.activeMilestone && state.phase !== "complete") {
    // Has active work - offer to continue or add milestone
    const choice = await showNextAction(ctx, {
      title: "GSD - Ready to continue?",
      // ...
    });
    
    if (choice === "add_milestone") {
      return showDiscuss(ctx, pi, base);
    }
  }
  
  // Default: start auto mode
  await startAuto(ctx, pi, base, false, options);
}
```

## Integration with Auto Mode

After discuss completes, auto mode uses the artifacts:

1. **Reads CONTEXT.md** for the active milestone
2. **Researches** technical approach (if needed)
3. **Plans ROADMAP.md** with slices
4. **Executes** slice by slice

See [Auto Mode](/commands/gsd-auto) for execution details.

## Best Practices

<Tip>
**Be specific about constraints.** Mention technical requirements (versions, deployment targets) during the discuss phase so they're captured in PROJECT.md and used during planning.
</Tip>

<Info>
**Front-load multi-milestone planning.** If you know you'll need M001, M002, M003 upfront, discuss them all in one session. The agent will create CONTEXT.md stubs for each, then auto mode will plan and execute them in order.
</Info>

<Warning>
**Don't skip the discuss flow.** Starting auto mode without PROJECT.md and REQUIREMENTS.md means the agent has no project context. Always run `/gsd discuss` first for new projects.
</Warning>

## Source Implementation

The discuss flow is implemented in `guided-flow.ts`:

```typescript
export async function showDiscuss(
  ctx: ExtensionCommandContext,
  pi: ExtensionAPI,
  base: string,
): Promise<void> {
  const state = await deriveState(base);
  const hasProject = !!(await loadFile(resolveGsdRootFile(base, "PROJECT")));
  
  if (!hasProject) {
    // New project - load discuss-new-project prompt
    const prompt = loadPrompt("discuss-new-project", {
      projectPath: base,
    });
    pi.sendMessage({ customType: "gsd-discuss", content: prompt, display: false }, 
                   { triggerTurn: true });
  } else {
    // Add milestone - load discuss-add-milestone prompt
    const prompt = loadPrompt("discuss-add-milestone", {
      projectPath: base,
      activeMilestone: state.activeMilestone?.id,
      queuePath: relGsdRootFile("QUEUE"),
    });
    pi.sendMessage({ customType: "gsd-discuss", content: prompt, display: false }, 
                   { triggerTurn: true });
  }
}
```

## Troubleshooting

### Discuss flow doesn't start

**Symptom:** `/gsd discuss` shows no response

**Solution:**
- Check that you're in a directory where you want to create `.gsd/`
- Ensure the agent is idle (not already running a task)
- Try `/reload` to reset extension state

### Context not used during planning

**Symptom:** Auto mode plans a milestone that doesn't match your discussion

**Solution:**
- Check that `M00X-CONTEXT.md` was written during discuss
- Review the CONTEXT file - ensure it captured your requirements
- Re-run discuss to refine: `/gsd discuss` (adds notes to existing CONTEXT)
